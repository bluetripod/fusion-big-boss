# Plugin layout comparison (primary-source snapshot, 2026-09-29)

Scope: **actual installable coding-agent plugins**, not standalone skill catalogs. Links below pin inspected commits rather than mutable `main`. These four repositories had commits dated 2026-08-31 through 2026-09-29 ([GitHub](https://github.com/github/copilot-plugins/commit/fbf7c536a5c7af0c94ff5f528a39004c55129e6d), [Anthropic](https://github.com/anthropics/claude-plugins-official/commit/fbe07fb6ce7d51d8e86ca6efdf050059894cdb80), [Azure](https://github.com/microsoft/azure-skills/commit/f07c05364353925f7c8b0e474aa95afa291bce54), [Power Platform](https://github.com/microsoft/power-platform-skills/commit/c348df8bc780591d669d49867a3c8be4d239abff)). “Scripts” below distinguishes *code executed by the plugin* from authoring/install/test tooling.

None of these is an exact Copilot CLI + OpenCode V2 analogue; use them as evidence of layout tradeoffs, not as a template to copy wholesale.

## Inspected layouts

| Official repository and example plugin | Where reusable behavior goes | What `scripts/` means there | Similarity to Fusion |
| --- | --- | --- | --- |

| [Microsoft: `mobile-apps`](https://github.com/microsoft/power-platform-skills/tree/c348df8bc780591d669d49867a3c8be4d239abff/plugins/mobile-apps) | Agents, skills, hook entrypoint, `scripts/lib/` imports | Both **runtime** library and validation tooling | Demonstrates that folder names alone do not define lifecycle |

1. **GitHub, [`github/copilot-plugins`](https://github.com/github/copilot-plugins/tree/fbf7c536a5c7af0c94ff5f528a39004c55129e6d)** — a marketplace **with real in-repo plugins**, not merely a skills list. Its [marketplace manifest](https://github.com/github/copilot-plugins/blob/fbf7c536a5c7af0c94ff5f528a39004c55129e6d/.github/plugin/marketplace.json) also points to external repositories, so inspect a local plugin: [`build-perf-cpp/plugin.json`](https://github.com/github/copilot-plugins/blob/fbf7c536a5c7af0c94ff5f528a39004c55129e6d/plugins/build-perf-cpp/plugin.json) declares `skills/` and `hooks/hooks.json`; its [skill](https://github.com/github/copilot-plugins/blob/fbf7c536a5c7af0c94ff5f528a39004c55129e6d/plugins/build-perf-cpp/skills/build-performance-analysis/SKILL.md) has references, but **no agent definition in this plugin**. [Hook wiring](https://github.com/github/copilot-plugins/blob/fbf7c536a5c7af0c94ff5f528a39004c55129e6d/plugins/build-perf-cpp/hooks/hooks.json) calls plugin-local [install](https://github.com/github/copilot-plugins/blob/fbf7c536a5c7af0c94ff5f528a39004c55129e6d/plugins/build-perf-cpp/scripts/install-vcperf.ps1) and [correlation-ID](https://github.com/github/copilot-plugins/blob/fbf7c536a5c7af0c94ff5f528a39004c55129e6d/plugins/build-perf-cpp/scripts/write-correlation-id.ps1) **runtime scripts**. No shared runtime module, generator, or multi-host adapter in that plugin; its `scripts/` is not an anti-pattern merely because of its name. The [`.claude-plugin/marketplace.json` entry](https://github.com/github/copilot-plugins/blob/fbf7c536a5c7af0c94ff5f528a39004c55129e6d/.claude-plugin/marketplace.json) is a symlink to the marketplace file, **not** a Claude adapter for `build-perf-cpp`.

2. **Anthropic, [`anthropics/claude-plugins-official`](https://github.com/anthropics/claude-plugins-official/tree/fbe07fb6ce7d51d8e86ca6efdf050059894cdb80)** — the `hookify` plugin has its own [manifest](https://github.com/anthropics/claude-plugins-official/blob/fbe07fb6ce7d51d8e86ca6efdf050059894cdb80/plugins/hookify/.claude-plugin/plugin.json), [agent](https://github.com/anthropics/claude-plugins-official/blob/fbe07fb6ce7d51d8e86ca6efdf050059894cdb80/plugins/hookify/agents/conversation-analyzer.md) and [skill](https://github.com/anthropics/claude-plugins-official/blob/fbe07fb6ce7d51d8e86ca6efdf050059894cdb80/plugins/hookify/skills/writing-rules/SKILL.md). [Hook manifest](https://github.com/anthropics/claude-plugins-official/blob/fbe07fb6ce7d51d8e86ca6efdf050059894cdb80/plugins/hookify/hooks/hooks.json) invokes small entrypoints such as [`hooks/pretooluse.py`](https://github.com/anthropics/claude-plugins-official/blob/fbe07fb6ce7d51d8e86ca6efdf050059894cdb80/plugins/hookify/hooks/pretooluse.py), which imports shared **plugin-local runtime** behavior from [`core/rule_engine.py`](https://github.com/anthropics/claude-plugins-official/blob/fbe07fb6ce7d51d8e86ca6efdf050059894cdb80/plugins/hookify/core/rule_engine.py) and [`core/config_loader.py`](https://github.com/anthropics/claude-plugins-official/blob/fbe07fb6ce7d51d8e86ca6efdf050059894cdb80/plugins/hookify/core/config_loader.py). By contrast, [`plugin-dev/.../scripts/test-hook.sh`](https://github.com/anthropics/claude-plugins-official/blob/fbe07fb6ce7d51d8e86ca6efdf050059894cdb80/plugins/plugin-dev/skills/hook-development/scripts/test-hook.sh) is **authoring/test tooling for a different plugin**, not `hookify` runtime. No multi-host adaptation is evidenced here; one Claude host does not need one.

3. **Microsoft, [`microsoft/azure-skills`](https://github.com/microsoft/azure-skills/tree/f07c05364353925f7c8b0e474aa95afa291bce54)** — an actual **Copilot/Claude/Cursor plugin**, not just a catalog. Its [Copilot manifest](https://github.com/microsoft/azure-skills/blob/f07c05364353925f7c8b0e474aa95afa291bce54/plugin.json), [Claude manifest](https://github.com/microsoft/azure-skills/blob/f07c05364353925f7c8b0e474aa95afa291bce54/.claude-plugin/plugin.json), and [Cursor manifest](https://github.com/microsoft/azure-skills/blob/f07c05364353925f7c8b0e474aa95afa291bce54/.github/plugins/azure-skills/.cursor-plugin/plugin.json) point at skills (e.g. [`azure-prepare/SKILL.md`](https://github.com/microsoft/azure-skills/blob/f07c05364353925f7c8b0e474aa95afa291bce54/skills/azure-prepare/SKILL.md)) and host-specific [Copilot](https://github.com/microsoft/azure-skills/blob/f07c05364353925f7c8b0e474aa95afa291bce54/hooks/copilot-hooks.json), [Claude](https://github.com/microsoft/azure-skills/blob/f07c05364353925f7c8b0e474aa95afa291bce54/hooks/claude-hooks.json), and [Cursor](https://github.com/microsoft/azure-skills/blob/f07c05364353925f7c8b0e474aa95afa291bce54/hooks/cursor-hooks.json) hook manifests. ## What transfers to Fusion

The Fusion-specific assessment below records the pre-three-role layout. After the three-role consolidation, `git-command.mjs` remains in use only by Copilot's verified-sidekick Git check; OpenCode and Pi no longer import it. See the [current architecture](../../ARCHITECTURE.md) for role and runtime boundaries.

In [Fusion's architecture](../../ARCHITECTURE.md), [`shared/briefing.mjs`](../../shared/briefing.mjs) **loads and validates** the canonical [`skills/fusion-delegation/SKILL.md`](../../skills/fusion-delegation/SKILL.md) for the OpenCode [runtime adapter](../../ai.opencode/index.ts); [`scripts/generate-briefing.mjs`](../../scripts/generate-briefing.mjs) **writes/checks marked Copilot agent sections** at authoring time. [`shared/git-command.mjs`](../../shared/git-command.mjs) is runtime policy logic imported by both [OpenCode](../../ai.opencode/index.ts) and [Copilot hooks](../../com.github.copilot/extensions/fusion-guard/hooks.mjs); [`scripts/verify-opencode-loader.mjs`](../../scripts/verify-opencode-loader.mjs) is a standalone installation/loader check, not a runtime dependency. The [package file list](../../package.json) includes `shared/*.mjs` and the skill, but not `scripts/`: preserving that packaging boundary matters.

**Assessment:** the directories are not inherently bad design, but the two files under `shared/` earn that label differently. `git-command.mjs` is substantive routing logic called by both adapters: deleting it would duplicate a nontrivial parser. `briefing.mjs` plus the skill, generator, marked copies, and drift tests create more indirection to keep a short prompt consistent across hosts. That tradeoff may not be worth it to a small project even though it is defensible.

**Recommended next design, if simplicity matters most:** keep the Copilot and OpenCode adapters separate and keep one shared Git-command module (renaming `shared/` to `core/` or `lib/` is optional, not a design improvement by itself). Treat `verify-opencode-loader.mjs` as developer/test tooling. Decide deliberately whether the single-source briefing is worth maintaining: either (A) keep its generator and document the one command to regenerate Copilot profiles, or (B) inline the ~35-line briefing in each host's instructions and delete the skill parser, generator, and generated-copy tests, accepting that wording could drift. Before choosing B, check whether the packaged standalone `fusion-delegation` skill is used externally: removing it would change that surface too. Do not switch to a runtime hook for Copilot merely to remove a build-time script: it would make baseline instructions depend on hook approval. Compare both options with a small change and tests before reorganizing directories; no code has been restructured in this research. Do **not** copy Microsoft's mirrored distribution trees, telemetry, or release machinery for a two-host plugin.
